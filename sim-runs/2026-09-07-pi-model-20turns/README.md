## 中继修复（2026-09-07）

历史实录保持原样。本目录脚本已修复提交挂起和归档后导入路径失效；运行当时的脚本可在提交 `2757d88` 中查看。启动入口为项目根目录下的 `npm run relay:start`。

客户端提交必须改为 `{ "stageId": "本次 pending.stageId", "output": { /* 对应阶段的完整返回 */ } }`。服务立即返回 `202` 表示已收件；通过 `/status?compact=1` 查看进度、`/pending` 读取下一阶段、`/metrics` 读取计算与等待耗时。收到 `202` 不等于内容通过校验；协议修复会获得新的阶段编号。重复提交同一编号和内容只确认收件一次。

诊断与测试口径见 [中继延迟诊断](../../docs/35_relay_latency_diagnosis.md)。该中继仍由外部调用方提供模型回复，不会自行选择或调用模型；本次本地性能回放也不替代这份真实模型记录。
