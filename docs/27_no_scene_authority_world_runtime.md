# v2.7：无场景裁决权的多地点人物世界运行时

> 状态：Phase 83 正式设计权威。望梯酒馆仍是第一套高精度验收夹具，但本文所有对象、协议和结算规则不得包含酒馆、固定人物或《逍遥游》专属答案。
>
> 人物会话运行与世界治理的实现补充见 `docs/28_pi_character_runtime_grok_world_governance.md`。该文只细化本设计，不改变本文的 Character Agent 选择权、世界单写入和无场景裁决权边界。

## 0. 结论

场景不是行动裁判，也不是事件菜单。

```text
不存在“酒馆允许／禁止什么事件”。
只存在：世界当前是什么，人物实际感知到什么，人物决定尝试什么，以及尝试最终造成什么。
```

地点可以让一个目标效果变难、变慢、产生损坏或引来他人回应，但不能替人物决定不去尝试。社会规矩、所有权、许可和职责也不是地点施加给所有人的统一数值；它们是世界中可以被人物知道、误解、认同、蔑视、违反并承担后果的事实。

新的生产权威由以下对象构成：

- `WorldEventJournal`：已提交世界变化与失败尝试的追加式事实源；
- `WorldCommitCoordinator`：客观世界的唯一写入者；
- `PlaceGraph`：空间、物质、实体、障碍和传播路径；
- `WorldProcess`：天气、水流、火势、生产、运输、疾病等持续因果进程；
- `CharacterSessionActor`：某个人物私有连续状态的唯一写入者；
- `PerCharacterEventReceipt`：事件对某个人的送达、注意、评价和消费来源；
- `WorldActionRegistry`：行动原语、参数与客观结算器，不生成候选、不选择人物；
- `Conversation / Commitment / SharedActivity / WorkProcess`：跨时间持续存在的交互对象；
- Observer、Narrator、Writer、UI：只读取已提交结果，不回流模拟。

## 1. “场景”需要拆成三个概念

### 1.1 `PlaceGraph`：客观地点

保存：

- 区域、边、距离、容量、遮挡、光照、噪声；
- 地面、墙、门、锁、水、火、桌椅、灶台等物质实体；
- 当前人物、动物、物件和容器的真实位置；
- 视觉、声音、气味、触碰和移动的传播条件；
- 所有权声明、告示、价格、门禁标识等可被感知的社会证据；
- 正在经过此地的天气、火势、水流、商队和工作进程。

不保存：

- `allowedActions` 或 `forbiddenEvents`；
- 人物应该履行的行为答案；
- 封闭候选列表；
- “酒馆不会发生洪水”一类场景类型结论；
- 对所有人物相同的规范压力。

### 1.2 `SituationProjection`：人物此刻得到的局部世界

同一地点对不同人物生成不同投影。它只包含本人通过感官、已有认识和当下注意真实获得的材料。盲人、剑术专家、疲惫者、经营者和专注寻找某物的人不会得到同一个世界切片。

### 1.3 `NarrativeScene`：面向观察者的成文单位

“清晨酒馆”“后院交手”可以是 UI 或 Writer 为阅读组织的叙事场景，但它没有任何模拟写入权。它不能决定谁出场、谁开口、何时发生事件或人物应当完成什么剧情。

## 2. 唯一因果链

```text
已提交世界状态与持续进程
  ↓ 物理传播
接收者专属感官证据
  ↓ Character Agent 注意、解释、相信、怀疑或忽略
人物调用私有心理数学工具
  ↓ 欲望、身体、关系、情绪、创伤、记忆与预期后果形成真实心理条件
同一 Character Agent 生成候选、选择、调节并具身表达
  ↓
ActionAttempt（人物真实尝试）
  ↓ WorldCommitCoordinator
WorldOutcome（成功／部分成功／失败及实际表面）
  ↓ WorldEventJournal
逐人物投影、回执、记忆、关系与下一次自主反应
```

调度器只授予一次思考机会；数学工具只构成人物此刻的心理；地点只提供事实；世界只结算尝试。四者都不能替 Character Agent 选择行动。

## 3. 客观不可能、社会越界与人物选择必须分开

### 3.1 物理结果条件

物理条件决定目标效果，不决定人物是否能形成意图。例如：

- 门锁着：人物仍可推门、敲门、撬锁、撞门、呼喊或离开；“直接穿门到达屋内”不会成功；
- 目标不在场：人物仍可喊名字、留言、误认旁人或对空处说话；目标不会收到不存在的直接对话；
- 剑收在远处：人物仍可伸手摸剑或声称有剑；拔剑效果不会凭空成功；
- 空间狭窄：人物仍可开打；步法、命中、碰撞和财物损坏会不同；
- 暴雨和河水上涨：任何地点都可能受灾，具体进水由地势、墙体、排水和水流进程决定。

世界应逐组成部分结算，而不是把整项尝试删除：

```js
{
  attemptSurface: "已经实际发生的伸手、迈步、说话或发力",
  intendedEffects: ["人物希望造成的效果"],
  resolvedEffects: ["真实成功的效果"],
  failedEffects: ["失败及原因"],
  incidentalEffects: ["声响、损坏、被看见、身体消耗等"],
  durationSeconds,
}
```

### 3.2 社会事实

所有权、许可、规矩、身份和职责由以下对象表达：

- 谁宣称拥有某处或某物；
- 谁曾公开提出什么要求；
- 谁承诺了什么；
- 谁具有何种能力、关系和制度位置；
- 当前有哪些潜在响应者；
- 过去的执行、处罚、纵容和例外记录。

社会事实不直接返回“不可选”。人物可以不知道、忘记、误认、不同意、故意违反或认为自己承担得起代价。

### 3.3 人物的规范压力

世界不再提供统一 `venueNormPressure`。人物可以使用同一私有工具计算：

```text
NormPressure_i(n,a)
= Belief_i(n)
 × [Internalization_i(n)
    + ExpectedSanction_i(n,a) × LossSensitivity_i
    + IdentityConflict_i(n,a)
    + ExpectedRelationshipCost_i(n,a)]
```

其中每一项都来自该人物自己的认识与性格。洛照可能因为厌恶麻烦而换地方；醉汉可能没意识到风险；店主可能因所有权和经营欲望出面阻止；急于求证的人也可能明知后果仍然拔剑。

## 4. 通用行动注册表不是场景能力菜单

`WorldActionRegistry` 始终认识全局行动原语：

```text
observe / listen / speak / move / touch / take / store / show
draw / strike / block / consume / transfer / pay / request
prepare / serve / work / damage / repair / carry / travel
```

地点无需“安装战斗能力”人物才可以挥剑，也不因安装“服务能力”就自动产生店员行为。结算器只读取当下组件：

- 人物身体、能力和姿态；
- 目标、工具和物件状态；
- 距离、障碍和传播；
- 实际资源、库存和耗时；
- 其他正在进行的动作与进程。

Character Agent 可以提出注册表尚未直接覆盖的复合行动。运行时将其拆成已知原语，或明确返回无法解释的目标效果；不得偷偷换成另一个“可行”动作。

## 5. 人物职责、服务与消费怎样自然出现

“酒馆有人招待客人”不能来自 `sceneRole=host` 的强制脚本。它应来自：

```text
人物实际看见来客
+ 本人知道这里由谁经营
+ 所有权／家庭关系／已接受分工
+ 赚钱、维持生意、照顾家人或避免失礼的欲望
+ 当下身体与其他任务
+ 对来客的第一判断
→ Character Agent 自己决定迎客、观察、让别人处理、怠慢或拒绝
```

服务也不是瞬时事务：点单、确认、取器具、生火、沏茶、端送、饮用、付款和收拾分别消耗时间并产生可见影响。人物可以被打断、忘记、插话、催促、赊账或反悔。

菜单来自库存、制作工艺、价格声明和经营者愿意提供的东西；修仙者是否消费、消费什么以及是否在乎价格，取决于其身体需求、财富结构、习惯、身份、目的和当下状态。

## 6. Character Session Actor

每个人物跨地点永久存在，并且只有自己的 Actor 可以修改：

- 身体与情绪连续状态；
- 主观信念、匿名人物模型和地点信念；
- 体验痕迹、召回实例和来源混淆；
- 欲望、意图、挫折和自我模型；
- 对关系的私人评价；
- 已接受承诺与本人对对话／共同活动的理解；
- 已提交的自身行动、语言习惯使用与调节消耗。

世界事件日志不直接写入信念或关系。它只产生可送达证据；Character Agent 在下一次 appraisal 中决定如何理解，Actor 再依协议提交私有更新。

单写入 Actor 不意味着人物被一个总 Agent 指挥。每个 Character Agent 仍是自己的选择权威；Actor 只保证本人状态不会被酒馆管线、后台模拟和另一个人物并发覆盖。

## 7. 世界事件日志与逐人物回执

### 7.1 事件信封

```js
{
  eventId,
  worldVersion,
  occurredAtSeconds,
  committedAt,
  type,
  actorId,
  placeId,
  zoneId,
  causalParentEventIds: [],
  actionAttemptId,
  publicPayload,
  privatePayloadRefs: [],
  statePatch,
  integrity,
}
```

日志必须：

- 只追加，不原地改历史事件；
- `worldVersion` 单调递增；
- 同一日志回放得到相同世界投影；
- 破损尾行最多丢失一条未完整事件；
- 快照只是加速，不能取代日志；
- UI 裁剪不能成为模拟事实丢失。

### 7.2 人物回执

同一个世界事件对每个人物拥有独立回执：

```js
{
  eventId,
  characterId,
  deliveryIds: [],
  status: "undelivered|delivered|noticed|appraised|consumed|expired",
  noticedEvidenceIds: [],
  appraisedAtAgentTurnId: null,
  consumedAtAgentTurnId: null,
  continuationIntentionIds: [],
}
```

规则：

1. 只有物理传播成功才可 `delivered`；
2. 收到不等于注意，注意不等于相信；
3. 某证据被本轮 appraisal 引用后，本轮结束必须至少进入 `appraised`；
4. 已被用于行动选择或明确选择忽略／延期后进入 `consumed`；
5. `consumed` 事件不能再次以 `new_external_impact` 唤醒同一人物；
6. 延期意图可以在时间到期或真正的新证据出现后另行唤醒，但不得把旧 delivery 重新伪装成新刺激；
7. 连续数秒的观察、停顿和开口可以属于一个带内部时序的 Agent 行动，不必拆成多个相同人物回合。

这直接针对 v2.6 Luna 样本中洛照已经在 step 3 使用谢真石目光证据，却在 step 4 又被同一 delivery 唤醒的问题。

## 8. 事件驱动调度

人物可能因以下事实获得一次思考机会：

- 新的感官证据达到本人可能注意的范围；
- 本人行动完成、部分完成或失败；
- 身体需要跨过阈值；
- 本人接受的承诺、计划或工作步骤到期；
- 对话或共同活动中真实轮到本人处理；
- 本人选择保留的 continuation intention 到达时间或收到匹配证据；
- 所在地点出现本人实际注意到的新资源、威胁或机会。

调度压力不能进入人物意识，也不能决定人物要回应。每次激活携带不可重复的 wake provenance；同一批证据只形成一个待处理 wake。多个近同时信号可合并，世界提交仍按 `worldVersion` 串行。

## 9. 持续交互对象

不同事情不得压成一个通用 `task`：

| 对象 | 权威与含义 |
|---|---|
| `Desire` | 人物私有，描述本人想体验或获得什么 |
| `Intention` | 人物私有，描述当前准备怎样推进，可改变或放弃 |
| `ConversationThread` | 各参与者分别保存自己的理解，不自动共享结案 |
| `Commitment` | 某人物公开接受后成立，可违约 |
| `SharedActivity` | 多方分别同意后成立，任何一方可撤回 |
| `WorkProcess` | 客观生产、修理、运输等进程，有资源和步骤 |
| `WorldProcess` | 天气、火势、水流、疾病等非人物专属进程 |

这些对象跨地点、跨日持续。人物离开酒馆不会丢失举荐承诺、伤势、未说出口的求助欲望或已经携带的物件。

## 10. 关系、记忆与传闻

- 一个动作只有实际传播到接收者后，接收者才可能评价它；
- 关系变化属于接收者 Actor，不由世界根据动作标签自动加减；
- 体验痕迹保存来源，回忆允许衰减、重构、混源和自我合理化；
- 传闻不是原事件跨地点穿透，而是知情人物后来实施的一次新表达行动；
- 听者获得的是二手证据，可以不信、误解、加工或继续传播；
- 人物说出的命题永远不会自动升级为世界事实。

## 11. 从当前代码迁移

### 11.1 保留并升格

- `characterAgentTurnProtocol.mjs`：五阶段同一人物 Agent 协议；
- `characterOperationalContinuity.mjs`：本人已结算行动的第一人称连续性；
- 人物相对感知、认知／记忆／表达分层、声音底座和共同活动分立同意；
- 现有物件、传播和世界结果合同中不依赖酒馆的部分。

### 11.2 必须退役的权威

- `causalSceneKernel.mjs` 中由 `scoreActionCandidates` 返回选中候选；
- `tavernCausalScene.mjs` 对调度、人物私有状态、世界事实和成文的多重直接写入；
- 场景提供“合法候选”、统一 `venueNormPressure`、静态 `accessStatus` 或职责映射；
- 把权限不足、人物不知道或行为不合习俗当作尝试前内容审查；
- 固定时段出场和双人轮换。

### 11.3 渐进纵切

不一次性重写 8577 行酒馆文件。每迁移一种权威，都必须：

1. 先用当前生产错误建立 RED 合同；
2. 新模块成为该纵切唯一写入者；
3. 旧管线只读取新结果或被显式禁用；
4. 回放同一事件得到同一结果；
5. 再迁移下一种行动或状态。

首个纵切为：`世界事件信封 → 洛照／谢真石 delivery → appraisal 消费回执 → 激活去重`。

## 12. 验收矩阵

### 12.1 权力边界

- 地点定义不含允许／禁止事件或人物行动答案；
- 心理数学工具保持 `selection: null`；
- 调度器输出 wake provenance，不输出候选或任务；
- 世界只提交客观结果，不写人物信念、关系或理由；
- Character Actor 以外的模块不能修改人物私有连续状态。

### 12.2 通用反例

1. 同一酒馆中，三个人对公开交手风险作出不同选择；
2. 未获许可者尝试进后院：可能敲门、闯入、撬锁或离开，不被统一删除；
3. 人物对不存在的目标喊话：声音真实发生，但目标未收到；
4. 暴雨与河水造成非预制地点进水，传播由拓扑和材料决定；
5. 店主因疲劳或私人冲突怠慢客人，场景不强制迎客；
6. 同一事件对已消费人物不重复唤醒，对新到场人物可以首次送达；
7. 传闻跨地点传播时保留每次转述来源和失真；
8. 人物跨酒馆、道路、宗门移动后保留物件、承诺、伤势和未决意图。

### 12.3 作者质量验收

确定性测试不能证明人物真实。真实模型样本仍由作者判断：

- 人物是否因自己的欲望、性格、状态和关系而行动；
- 违规、克制、冒险和退让是否属于这个人，而不是场景模板；
- 台词是否有情绪、潜台词和个人声音；
- 连续时间内是否真正记得刚发生的事；
- 多人物是否各自拥有不同理解，而不是围绕同一全知叙事轮流发言。

## 13. 实施顺序

```text
P0 冻结 v2.6 基线与失败证据
→ P1 权威文档和 Phase 82 状态同步
→ P2 世界事件日志与确定性回放
→ P3 逐人物事件回执
→ P4 酒馆激活链纵切与重复唤醒修复
→ P5 物理条件／社会事实／人物评价拆分
→ P6 Character Session Actor 与世界单写入
→ P7 通用行动注册表
→ P8 活动、承诺和世界进程账本
→ P9 酒馆数据化迁移
→ P10 多地点、多人物、跨日真实验收
```

本阶段不通过新增场景专用管线证明泛化。真正完成的标准是：换地点只改变世界实体、拓扑和进程，不重写人物决策、记忆、调度、传播和结算。
