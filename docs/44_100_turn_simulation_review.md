## 主要问题与证据

### 1. 动作描述越过了实际物品结算

第 52、66、75、92 回合的文字描述木头劈开；实际 primitive 都是 gesture，只有 gesture_performed，没有柴堆数量变化。第 98 回合的“柴垛码正”也是同样情况。97 条世界事件中，涉及 objects 的修改只发生在世界版本 3（洛照占座）、9（药包放置）、28（真石移动时随身短剑位置跟随），完全没有柴、水或斧头的状态修改。

| 项目 | 最终客观状态 | 与文字的出入 |
|---|---|---|
| 待处理湿柴 | unprocessedBundles = 2 | 没有扣除任何一束。 |
| 成柴 | processedBundles = 0 | 与“五斧落地、柴账收讫”的总结矛盾。 |
| 水缸 / 水桶 | 水缸 fill = 0.55；水桶 fill = 0 | 没有挑水、添水完成。 |
| 劈柴斧 | holderCharacterId 为空，returned = true | 没有拿起斧头的物品操作；身体文字反复说持斧。 |
| 柴水职责 | progress = 0，status = active | 仍未完成。 |
| 药包 / 清单 | 药包放下但 accepted = false；清单仍由周珉持有 | “药包连同清单”在描述中一起放下，实际只操作了药包。 |
| 茶碗 | contents = empty | 第 24 回合 interact 并未生成茶；第 42 回合 consume 失败。 |

生成端使用 act / observe / rest 搭配宣告结果的文字；程序将 act 映射为 gesture，又把这段文字直接写入公开事实和他人感知。这是生成端选择错误与程序语义约束不足共同造成的。物品结算没有被文本直接篡改，但公开叙述已经与它分叉。

[act 到 gesture 的转换](/src/server/pipeline/tavernCharacterAgentV2.mjs)（worldAttemptPrimitive，约第 3159 行）；[手势结算与视觉投递](/src/server/simulation/worldActionRegistry.mjs)（settleGesture，约第 448 行）。已有柴务模板定义了每束 42 秒及柴堆增减，见 [柴务模板](/src/worldbuilding/skills.js)；本次没有调用出这样的客观工作过程。

### 2. 等待和准备动作反复生成，缺少真正的工作与重新判断

第 22 回合真石说“好。柴水齐了，一起说。”之后，直到第 31 回合才真的移到后院，第 52 回合才首次写落斧。第 46、49 回合文字都说“最高处停半息”，实际各结算 30 秒休息。洛照反复“息沉腹底、耳门当值”，周珉反复“坐实、默数”。末段候选仍局限于休息、倾听、观察，或把真正拿桶写成 act。

97 个行动回合中，96 个由 world_evidence 唤醒，另 1 个是第 4 回合洛照的 continuation_due；三人的反思事项已进入待办，却没有一个反思回合执行。最终反思累计重要性分别为 46.3、57.9、65.3，阈值均为 4。结合世界证据优先于计划/反思的排序，反复的自身动作反馈和旁人姿态很可能长期挤占了重新判断的机会；这属于调度风险，不能只归因于模型爱等待。

### 3. 声音与动作也未保持一致

描述里的“脆响”随 gesture 作为 visual 投递，没有创建对应的声音信号。21 次 listen 中有 20 次 LISTEN_NO_AUDIBLE_SIGNAL，得到的是部分成功：倾听动作成立，但没有听到目标信号。报告把两人“数斧声”写成客观推进，与这份听觉结算不符。

### 4. 同类协议错误没有收敛

161 条 rejected 阶段里，99 条发生在组合选择/提交阶段；96 条包含 CHARACTER_AGENT_AFFECTIVE_INFLUENCE_LIVE_SOURCE_IGNORED。候选阶段还有 54 条包含 AGENT_CANDIDATE_EPISTEMIC_POSITION_REQUIRED。一个阶段可能含多个错误码，不能将错误码次数直接相加。95 次随后出现 commit-only 阶段并成功，说明大部分回合靠补交才走完。

末轮原始 choice 文件仍写 sourceEmotionIds = []、mode = no_live_influence；commit-only 文件再补入 anticipation、excitement、joy、pride、curiosity。这至少说明生成端与组合阶段所需的情绪状态持续不匹配。未逐个保留全部历史输入窗口和修复前原稿，不能仅凭这些文件把 96 次的根因全部归于一方。

### 5. 运行总结需要纠正

原总结说“97 action turns + 3 maintenance turns，全部世界结算成功”，实际为 76 成功、20 部分成功、1 失败。原总结的 HALT 次数出现 2、3、4 等不同口径；保存的运行错误为 5 条，跨 6 个 runId。“五声同正”也缺少第二斧的已结算记录，并且四次落斧文字本身都没有加工柴。

模型来源：保存的 provenance 是 external-unverified / modelVerified=false。原总结自称本 Pi 会话 Omen Alpha 生成，但没有可核验的模型提供方调用记录；本复核不将它标为 Sol 或 Luna 的测试成绩，也不据此断言内容不是模型生成。

## 建议优先顺序

1. 先对齐操作与效果：让劈柴、取水、倒茶、组合物品交付使用能改变世界的操作；约束手势和身体描述，避免把未结算结果传播给其他人物。
2. 处理无进展唤醒：等待角色应能等到真实事件或超时再行动；减少重复姿态和自身结果引发的循环，并保证到期计划/反思有执行机会。
3. 对齐模型提交阶段与情绪状态：避免几乎每轮先触发同一个拒绝再补交；缩小修复回合并保留实际阶段输入/输出证据。
4. 报告按物品变化、承诺兑现、交互结果衡量推进；回合数与成功标志只作为运行统计。
