# 本地人物活动快速模式

已实现第一阶段优化。进入主界面的「现实空间 → 人物自决」，选择「快速」，再点击「开始活动」。也可以在活动过程中直接切换速度。

| 模式 | 上一回合完成后等待 |
|---|---:|
| 正常（默认） | 2.1 秒 |
| 快速 | 0.2 秒 |

速度只影响现实中的等待时间。人物仍按顺序完成回合，模拟世界的时间、行为、事件与逐回合持久化保持原有规则。切换时会替换尚未触发的计时器；正在进行的回合完成后使用新速度。停止不会中断正在提交的回合，也不会再启动下一回合。

速度选择会保存。刷新或读取存档后保持暂停，点击「开始活动」才能继续。本机已有 Node.js 25.6.0，满足项目 Node.js 24+ 要求，无需安装。

## 浏览器实测

在本机独立浏览器会话和临时服务端数据目录中，从同一个已完成首回合的不可变存档分别恢复两份世界，各推进 100 个回合。使用主 UI 的本地确定性运行时，两个活动人物，开启日计划。测试按快速、正常的顺序执行一次，包含真实 HTTP、持久化、浏览器渲染和展示等待；没有调用外部模型。计时期间未运行完整测试套件。

| 指标 | 正常 | 快速 |
|---|---:|---:|
| 100 回合总耗时 | 246.35 秒 | 57.32 秒 |
| 相邻回合完成间隔 p50 | 2,493.4 ms | 577.8 ms |
| 相邻回合完成间隔 p95 | 2,718.0 ms | 797.2 ms |
| HTTP 请求耗时 p50 | 352.4 ms | 344.9 ms |
| 同时进行的请求数上限 | 1 | 1 |

这组测试约快 **4.30 倍**，总耗时减少 **76.7%**。先前约 6.2 倍是使用较短的服务端基线加展示等待得到的估算；本次实际浏览器负载包含更长历史和页面开销。结果只代表这组本地测试，不能解释为真实模型推理提速。

每组包含 93 个行动、2 个日计划和 5 个反思回合。并非每个回合都会改变世界版本；两组都从世界版本 1 到达版本 89。100 次返回的公开世界投影逐条完全一致。服务端完整 checkpoint 在仅排除事件实际提交时间及其对应校验摘要后也完全一致，涵盖人物内部状态、事件、回执和待执行队列。

逐回合原始计时与核对结果见 [浏览器实测 JSON](./33_npc_activity_browser_benchmark_2026-09-06.json)。这是一次成对测量，没有把单组数据当作长期性能保证。

## 刷新故障修复

浏览器验收发现，带有已结算动作效果的世界在刷新时会触发 `PUBLIC_RUNTIME_SCENE_EFFECT_TEXT_FIELDS` 初始化错误，随后被原有异常回退逻辑重置为初始世界。

根因是状态模块先读取存档，再初始化迁移时需要的效果字段列表。本次将读取存档移到这些列表之后，保留存档格式。新增测试用一个包含动作效果的已完成回合重现完整的模块重新加载，先确认失败，再验证修复后世界身份、回合、历史、游标与快速档均保留。

## 验证结果

- 完整回归：**531 / 531 通过**，76.5 秒。
- 语法检查与差异格式检查通过。
- 自动检查覆盖回合进行中切换、等待期间切换、取消后迟到的回调、停止后重启、失败停止和速度偏好迁移。
- 浏览器中特意延迟一个已提交回合的响应，连续切换正常/快速后点击停止：最终只结算原来的一个回合，没有额外请求或遗留待决命令。
- 正式保存与读取恢复了世界版本 90 和现有历史；刷新保留同一世界及快速档，并保持暂停；随后成功推进到版本 91。
- 1280 px 桌面和 390 px 窄屏布局检查通过，窄屏页面没有横向溢出。
