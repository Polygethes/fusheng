# 提交与行动反馈修复

日期：2026-09-09。针对第 51–60 回合暴露的提交错误、持物状态不清、失败反馈含糊和战报失真。模拟由用户自行进行，本次没有调用真实模型。

本文是 v1 的历史修复记录。当前中继已使用 v2：`POST /respond` 的 422 会消耗一次有界提交，不能沿用旧阶段改写内容；只读预检使用 `/validate`。当前操作说明见 [场景进展、物品反馈与恢复修复](48_scene_progress_grounding_repairs.md)。

## 当时已完成（v1）

1. **提交前检查。** 中继先按当前阶段的输出约束检查格式、合法动作、引用和对话组合。错误返回 HTTP 422，并保留原 `stageId`，不会唤醒运行时或消耗人物回合的协议修复次数。可以先调用只读的 `POST /validate`。预检拒绝单独计数，不伪装成零错误。
2. **减少机械填写。** 适配器可补齐缺失的固定身份、回合及上一行动编号；如果提交了矛盾的编号或身份，会拒绝，不覆盖。不会代填对白、欲望、行动选择或情绪判断。
3. **明确修复阶段。** 输入中的修复规则已更正：选择失败仍提交 `{choice, turnCommit}`；选择通过但动作提交失败，则保留已通过的选择，进入独立 `turnCommit` 阶段。中继输入附带 `submissionContract`，列出本次必需的顶层字段。
4. **重试配置生效。** 移除了把配置值 2 强制压成 1 的逻辑。修复次数在一次人物回合内共享，达到配置上限仍会停止；不会自动清除存档中的停止标记。有效配置为 0–10 的整数。
5. **引用与动作参数一致。** 锁定本轮行动编号、上一行动编号和可选候选；对话锚点与参与者成组约束。修正了输出约束与运行时不一致的问题：物品操作仍锁定选中的物品，但允许填写接收者；移动可填写当前可知的目的地；伴随动作发声可以填写合法的接收者。其他不相关参数仍受约束。
6. **明确沿用心理状态。** 新增可选字段 `epistemicPositionUpdateMode: "retain_unmentioned"`。人物明确选择此模式后，只需提交新增或改动的立场，程序沿用仍在感知范围内的其他既有立场。改动以人物本次提交为准，旧证据不会自动变成本轮新观察。省略此模式仍按完整列表验收，未决立场不能静默消失。
7. **持物状态与执行规则一致。** 自己的物品使用物品结算模块的同一套携带默认值。即使旧存档没有写 `custody`，也会明确呈现“随身携带，但尚未拿在手中”，不再显示空对象让提交端猜测。不会把别人的隐藏物品状态投给人物。
8. **分开反馈说话和物品操作。** 本人回执明确说明“话已经说出”“展示/递交未完成”“物品尚未拿在手中”；对本人的包内物品也会说明仍在容器内。具体失败码继续保留在记忆中。程序不会自动取出、转交物品，也不会把人物的主观成功判断强改成某个分数。
9. **结算报告。** 每次保存都会生成相邻的 `.report.md`，也可以读取 `GET /report`。报告只列世界结算确认的对白与结果，私人意图、反思和拒绝稿不作为已经发生的行为。反思输入补充了原始感知、行动结果与个人解释的区别说明。
