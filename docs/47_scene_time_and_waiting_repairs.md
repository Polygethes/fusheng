# 场景时间与等待修复

日期：2026-09-15。基线：`0490a5e`。

## 问题与改动

最近的 100 回合原始模拟只推进 1114 秒，最后一段对白出现在第 22 回合。原始计划曾为入座观察安排 4200 秒，为等待安排 7200 秒。世界实际只运行三个人物，收件人谢母没有参加。这些不是单靠换模型就能消除的条件。

本次为新模拟启用 `scene` 时间策略。人物仍决定做什么、说什么、是否改变主意；运行时负责时间、实际物理结果、重复消耗的边界与客观事件投递。

| 环节 | 新场景行为 |
| --- | --- |
| 私人规划 | 展望未来 30 分钟，写 1–4 个近期时间块，每块不超过 5 分钟；无需填满整个时段 |
| 对白 | 保留逐轮评估与回应；时长按中文字符和其他语言词数估算，中文默认每秒 4 字 |
| 观察、倾听 | 默认分别推进 5 秒、10 秒 |
| 休息 | 默认推进 2 分钟；遇到已排定的过程或时间边界会提前结束这段时间 |
| 持续工作 | 显示完整工作单元的预计耗时；人物开始后，沿已有过程推进到就绪或打断点，不反复请求同一个起手动作 |
| 明确等待 | 没有新的可执行回合时，跳到最早的真实事件、本人期限或运行目标，不用模型轮询空白时间 |

做工与移动继续使用原有物理耗时；本次没有把每种动作统一放大。对白时长是可检查的模拟规则，不是实测语速。对话和正在结算的普通动作仍是完整节拍，不提供逐字中断。

## 时间会形成什么后果

新场景默认在开始后 15 分钟核对开门前的柴水准备，未齐时提前 5 分钟提醒。时间可以配置。这个默认值是新加入的场景设置，不冒充原作已经确定的钟点。

到时要求成柴至少 2 束、水缸装满。世界根据实际资源判定：

- 按时齐备：记录准备完成。
- 到时未齐：记录营业准备延误，并持续累计超时。
- 超时后补齐：记录迟到完成及实际完成时间。

提前齐备不会立即锁定成功；若期限前又消耗掉资源，到点仍会如实判为未齐。完成时间也不会因为随后一句较长对白而被误报为迟到。时间事项和结果写入存档、结算报告，并在恢复后保持一致。

人物收到的是其所在地点的时间提醒。藏在其他区域的库存不会通过提醒自动变成其亲见知识。系统没有虚构营业收入损失、强制客人出现、返宗日期或考核截止日；这些更具体的设定需要场景自身提供。

## 重复等待与恢复

人物再次考虑行动时能看到本人刚才等了多久、是否到期、相关事实有没有改变。连续两次无变化的等待到期会触发一次本人反思；反思后仍重复无效等待，则将该人物暂停为 `stalled`，避免把整批回合耗在相同循环上。

交替“看—听—休息”也会检查是否只是在重复已有动作。新的相关事实、实际工作进展或身体恢复会重置相应计数，不把有效休息算作空转。

暂停的人物可以被新的相关世界事件重新唤起，包括对白、期限提醒、过程就绪和实际交付。已处理事件的重放不能再解锁一次。模型协议耗尽导致的 `suspended_model_error` 保持独立，不会被普通时间提醒重置。

系统不会替人物挑一个更有戏剧性的行动。若人物复核后仍坚持相同等待，会明确暂停，不能保证所有模型都能自行产生精彩故事。

## 送药能够实际完成

新场景运行谢真石、洛照、周珉、谢恒和谢母。默认真石、洛照、周珉在堂前，谢恒在柜台，谢母在灶边；浏览器模型入口继续保留洛照从门口开始的原有位置设置。

当前引擎补上 `accept_delivery`：物品实际交到指定收件人手中或放到其面前后，由收件人选择核对验收。药包和清单各有独立的验收记录。隔着空间、仍被别人拿着、由错误的人验收、重复验收都不会算成完成；“药和清单都收好了”的自由文字也不能一次改变两件物品。

## 入口与配置

| 入口 | 新模拟默认值 | 修改方式 |
| --- | --- | --- |
| 自动模型运行器 | `scene`，15 分钟开门准备 | `--pacing scene`、`--opening-seconds 900` |
| HTTP 中继 | 同上 | `RELAY_PACING_MODE`、`RELAY_OPENING_SECONDS` |
| 浏览器持久会话 | 同上 | `GTOWN_V27_PACING_MODE`、`GTOWN_V27_OPENING_SECONDS` |
| 文件桥 | 同上 | `TAVERN_V27_PACING_MODE`、`TAVERN_V27_OPENING_SECONDS` |

开门准备时长允许 60–86400 秒。`day` 保留一天 5–8 块的诊断策略；底层库的无参数调用也继续默认 `day`，避免改变已有按日生活测试。使用固定旧计划的历史延迟测试默认使用 `day`。

保存恢复沿用存档中的人物和时间策略。旧存档不会自动补出谢母或新增期限；重新从旧会话定义重置，也不等于采用新的定义。完整使用本次配置应新开模拟或新建分支。两个原始测试目录保持原样。

浏览器服务重启后，新建会话才使用新入口配置。每条继续命令仍只处理一个人物回合，未完成的失败回合优先接续，再处理新排入的私人计划。
