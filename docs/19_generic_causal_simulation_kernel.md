## 结论

望梯酒馆不再被视为引擎本身，而是第一套场景适配器。通用底层只认识：人物、场景、区域、物件、影响、关系、欲望、承诺、候选行动和证据；它不认识酒馆、固定姓名或《逍遥游》的剧情语义。

同一个人物决策过程是：

```text
已提交世界状态
→ 本人实际感知到的影响
→ 场景适配器提供合法候选
→ 硬门控
→ 义务层级
→ 人物权重下的数学效用
→ 原子提交行动
→ 传播影响
→ 接收者主观评估
→ 关系、身体、欲望与承诺更新
```

模型只可实现已经选定的动作和说法，不可更换行动者、对象、位置、物件、事务结果或因果来源。

## 统一选择公式

候选行动先经过硬门控：

```text
Fᵢ(a,t) = ∏ₖ 1[preconditionₖ 成立]
```

目标不在场、声音未抵达、物件不在手边、位置不合法、承诺前置步骤未完成时，行动直接不可选，不允许用高欲望抵消事实错误。

合法候选按二元序排序：

```text
Rankᵢ(a,t) = (Priority(a,t), Utilityᵢ(a,t))
```

其中义务层级是词典序优先，而不是普通加分：

```text
3                 当前已经送达、正在等本人回答的请求
1 + p             本人已经接受的承诺或事务，0 ≤ p ≤ 1
p                 尚未接手但与本人职责匹配的现实事件
0                 私人欲望与日常行动
```

这并不强迫人物同意请求。回答、拒绝、说明条件或明确延期都可以关闭当前回应义务；不能用练剑、休息或无结果走位假装请求不存在。

同一层内使用共享效用函数：

```text
Utilityᵢ(a,t)
= Σₖ w⁺ᵢₖ · f⁺ₖ(a,Sᵢ,E,R,C)
- Σⱼ w⁻ᵢⱼ · f⁻ⱼ(a,Sᵢ,E,R,C)
```

正向因子包括欲望推进、职责、机会、关系牵引、情绪推动、创伤冲动、身体恢复、承诺压力；负向因子包括安全、身体消耗、环境阻力、公开抑制、关系伤害、切换成本和重复惩罚。公式相同，每个人的权重、身体、情绪、关系和当下意图不同，所以选择不同。

创伤冲动会受亲密关系缓冲，但不会被亲密关系删除：

```text
TraumaEffective
= TraumaRaw × Activation × Impulsivity × Arousal
× max(0.15, 1 - RelationshipBuffer)
```

因此“被触发但面对亲近的人”可能变成压住火气、追问、退开或较轻的对质；是否爆发仍由全部候选的净效用决定。

## 场景适配器

每个场景只提供数据：

```js
{
  scenes,
  zones,                 // sceneId、区域 id、公开度、隐私、规范
  edges,                 // movement / sound / visual 的路径和阻隔
  responsibilityRules,   // 哪类实际事件匹配哪种能力
  objects,
  affordances
}
```

不同场景可重复使用 `hall`、`deck` 等局部区域名；内核用 `sceneId + zoneId` 组成碰撞安全的位置身份。同名区域不代表相连，也不能产生跨场景对话。

人物使用通用 `agency`：

```js
{
  traits,
  weights,
  currentState,
  capabilities,
  responsibilityPriority,
  knowledgeBoundary,
  desires
}
```

旧酒馆人物的 `tavernAgency` 只作为兼容输入；新场景和新人物不需要使用该命名空间。

## 证据闭环

动作不会因为文本声称成功就改变世界。一次提交必须同时通过：

- 空间与传播校验；
- 物件所有权和原子事务校验；
- 承诺图的责任人、区域、物件和前置步骤校验；
- 欲望满足证据校验。

关系变化只作用于真正收到该动作影响的人。远处、隔墙或另一场景的人不会因为作者知道事件就改变关系。

欲望只在行动携带匹配的 `satisfactionEvidence` 后满足。相似文字、同类动作或时段结束都不能替代证据。未满足的欲望继续积累；已满足的意图关闭，不再循环重复。

## 多场景传播

直接视觉、声音和触碰只按当前场景拓扑传播。跨场景信息必须经过一种新的、可追溯的行动：

```text
甲亲眼看见事件
→ 甲保存带来源的观察
→ 甲在另一场景实施转述/传闻行动
→ 乙实际听见
→ 乙形成置信度较低的二手信念
```

传闻不是原事件穿墙传播；它是另一个人物后来实施的新行动，并保留来源链。

## 当前验证

`causalSceneKernelGeneralization.mjs` 使用完全不同的天文台和渡船适配器，验证：

- 任意人物 ID 和通用 `agency`；
- 责任事件胜过无关私人行动；
- 物件事务原子提交；
- 影响只在真实空间范围传播；
- 关系只改变实际接收者；
- 欲望只由匹配证据关闭；
- 跨场景同名区域不能交谈；
- 同场景明确呼喊可以沿声音路径抵达。

酒馆现有事务层继续负责来访、工作、服务、付款和住宿等领域规则，但其选择、空间、物件、传播、关系、欲望满足和职责匹配已经使用同一组通用模块。以后换场景时，只替换适配器数据和领域事务，不复制人物决策公式。
