# 长测恢复与 Gemini API 接续

本轮修复针对长测中暴露的交付参数冲突、关系更新晚期停机、无效引用和预算耗尽后缺少可审计恢复路径。

## 修复范围

- `transfer` 同时需要物品与收件人。绑定收件人后不再把物品强制置空；最终动作校验也检查两者，覆盖不同阶段调用模式。
- 后续意图的目标只能引用本轮可见句柄；持续欲望的激活状态不能填潜伏。线索触发型欲望若填 active/triggered，必须提供激活证据。候选的反事实结果不能为空。
- 关系更新的第一手证据检查与私有状态结算共用同一规则，能识别匿名人物的感知句柄；传闻仍不能自动变为第一手证据。错误在人物的评估阶段返回给同一模型修复。
- 关系 impact 引用也需经过已注意证据检查；`none` 关系更新不再携带无关来源。
- 正常重启仍不重置预算。`authorizeCharacterTurnRetry` 必须带授权编号和原因，保留已接受阶段、原始输入、调用计数、被拒回复和授权历史；同一授权重复执行不增加额度。已收到尚未结算的有效回复不得丢弃。
- 执行器尊重显式配置的修复额度，不再硬截为两次。默认仍为两次，三阶段人物回合总调用上限为 `3 + maxRepairs`，外部测试另有总请求上限。

## API 接续入口

`npm run gemini:simulate -- --resume <world-save.json> --out <新的目录> --turns 10 --max-requests 60 --repairs 4 --model gemini-3.8-flash-medium --response-format json_object --retry-authorization <本次授权编号>`

密钥只从进程环境 `GEMINI_API_KEY` 读取。`GEMINI_API_BASE_URL` 不设置时调用 Google 原生接口；设置为用户指定网关后使用其 OpenAI 兼容 `/v1/chat/completions` 接口。不要在命令参数、项目文件或报告中填写密钥。

不同服务的模型别名可能不同，应先确认该服务返回的模型列表。记录会分别保存请求模型和服务返回模型；网关声明不能当作独立的上游模型身份认证。

默认使用 `json_schema`。若网关拒绝复杂 schema，可显式使用 `json_object`：完整 schema 进入提示，所有本地校验保持不变。仅完整 Markdown JSON 外壳可以去除，正文及人物决定不被补写。无效 JSON 返回给原人物的有限修复循环，不因此中止整局。

修复请求携带同一人物、同一回合、同一阶段上次被拒的原文。角色之间不共享回复缓存，新的阶段也不继承其他阶段的被拒内容。

## 记录与验证边界

输出目录必须是新目录，源存档不会被覆盖。保存初始快照及源哈希、每次 API 请求正文（无鉴权头）、原始响应、用量、阶段拒绝、最终检查点和新增回合报告。`--dry-run` 只验证恢复路径并准备第一阶段，模型请求数为零。

`npm run long-run-recovery:test` 验证新修复与 API 适配契约。模拟报告单独列出真实行动、部分成功、失败、人物暂停状态和实际世界资源变化；完成指定回合数不代表故事质量或场景目标通过。
