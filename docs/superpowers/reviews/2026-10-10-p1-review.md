### A1. 切回“Gemini 官方”后，密钥仍发往旧网关

**复现（已在浏览器确认）：**
1. 设置里选“OpenAI 兼容网关”，填 `https://127.0.0.1:9/v1`，保存。
2. 改选“Google Gemini API（官方）”，保存。
3. 结果 `/api/settings` 是 `provider: "gemini"`，但 `baseUrl` 仍是旧地址。`/api/runs` 的 `gateway` 显示 `127.0.0.1:9`，真实运行会把密钥发到旧网关。
4. 同时“测试连接”按 `provider` 测的是 Google 官方，所以测试结果和真实运行不一致。

**修法：**
- `src/server/localData.mjs`：
  - `normalizeSettings`：`provider === "gemini"` 时 `baseUrl` 一律为 `""`。
  - 新增 `export function modelApiBaseUrl(settings)`：gemini 返回 `"https://generativelanguage.googleapis.com"`，openai-compatible 返回 `baseUrl`。
  - `modelEnv` 只在 `provider === "openai-compatible"` 时设置 `GEMINI_API_BASE_URL`，否则删除它。
  - `validateSettingsPatch(patch, current = {})` 改为校验合并后的结果：provider 和 baseUrl 都取 `patch ?? current`。只改 provider、而地址已经保存过时，不应报“网关需要填写地址”。
- `src/server/observer/settingsApi.mjs`：
  - 测试连接改用 `modelApiBaseUrl(current)`。
  - PUT 调用 `validateSettingsPatch(patch, current)`。

**契约（加到 `scripts/localDataContracts.mjs`）：**
- 先存网关配置，再 `writeSettings({ provider: "gemini" })`：读回 `baseUrl === ""`，且 `modelEnv(...)` 里没有 `GEMINI_API_BASE_URL`。
- 已存网关地址时，`validateSettingsPatch({ provider: "openai-compatible" }, saved)` 返回 `[]`。

### A2. 本机服务可被 DNS 重绑定利用，偷走密钥

P1 之前，密钥只在进程环境里，HTTP 改不了请求去哪。现在 `PUT /api/settings` 能改网关地址，`POST /api/settings/test` 又会立刻带着密钥去请求这个地址。

恶意网页只要用 DNS 重绑定把自己的域名指向 127.0.0.1，`Origin` 和 `Host` 就是同一个域名，`sameOrigin` 会放行。两次请求就能把密钥发到对方服务器。这个下载版必须防。

**修法：**
- 新建 `src/server/localGuard.mjs`，导出 `isLocalHostHeader(hostHeader, port)`。
  - 只接受 `localhost`、`127.0.0.1`、`[::1]`（可带 `:port`，端口须等于服务端口）。
  - 如果 `process.env.HOST` 不是这几个值，也加入它。
- `server.mjs`：所有 `/api/` 路由之前，Host 不在白名单就返回 `403 { code: "HOST_FORBIDDEN" }`。
- 纵深防御，在 `settingsApi` 的 PUT 里加一条：合并后的请求地址（`modelApiBaseUrl`）的 host 和当前不同、当前已有密钥、而本次没带 `apiKey` 时，返回 `400 { code: "KEY_REQUIRED_FOR_NEW_HOST", message: "换了请求地址，请重新填写密钥。" }`。
  - 这样密钥不会被悄悄改道。
  - 设置弹窗在提供方或地址改动时，在密钥框下提示这一点。

**契约：**
- `scripts/localGuardContracts.mjs`：
  - 用 `http.request` 自设 `host` 头，`evil.example:PORT` 返回 403。
  - `127.0.0.1:PORT` 和 `localhost:PORT` 正常。
- `settingsApiContracts`：
  - 已存密钥时，只改 `baseUrl` 返回 400 `KEY_REQUIRED_FOR_NEW_HOST`。
  - 同时带新密钥则返回 200。

### A3. 导入不校验，坏世界会存进库里然后“消失”

**复现：** 用 `{ format: "character-town-world", formatVersion: 1, pack: { meta: { id: "broken" }, cast: "nope" } }` 调 `importUserWorld`。
- 导入成功，`listUserWorldIds` 里有 `broken`。
- 加载时报 `WORLD_PACK_SECTION_MISSING`。
- `/api/library` 吞掉错误，不显示它。
- `runsApi` 仍把它当合法世界 id 接受。

**修法：**
- `importUserWorld`：保存前依次做 `defineWorldPack` → `validateWorldPack`（`ok` 为 false 就拒绝）→ `runWorldSmoke`（有 issues 就拒绝）。
  - 抛出 `fault("WORLD_PACK_INVALID", ...)`，附带 `issues`。
  - `worldsApi` 返回 `400 { code, issues }`。
- `saveUserWorld`：同样做 `defineWorldPack` + `validateWorldPack`。冒烟留给编译器自己跑。

**契约：** 上面的坏包导入被拒（`WORLD_PACK_INVALID`），世界库目录里没有它。

### A4. 契约会读到本机真实的 `~/.character-town`

- `observerRunsApiContracts.mjs:42` 断言世界列表恰好是 `["jiexing", "xiaoyaoyou"]`。
- `worldSmokeContracts`、`worldPackValidatorContracts` 会遍历 `listWorldPackIds()`。

玩家一旦存了自己的世界，测试结果就取决于这台机器。

**修法：** `scripts/runContracts.mjs` 开始时 `mkdtemp` 一个目录。`spawn` 时传 `env: { ...process.env, CHARACTER_TOWN_HOME: <临时目录> }`，结束时删除它。

**验证：** 在真实 `~/.character-town/worlds/` 放一个 `jx_copy` 副本后，`npm test` 仍然全绿。验完删掉这个副本。

### A5. 开始面板的默认模型被悄悄改了

改之前，“新的开始”面板的模型默认是 `gemini-3.8-flash-high`。现在即使没有保存过设置（只用 `.env` 的老用户），`ui.js` 也会把它换成 `normalizeSettings` 的缺省值 `gemini-3.8-flash`。用户重启服务后，下一次运行会换模型而不自知。

**修法：** 只有 `settingsRes.settings?.configured` 为真时，才用 `settings.model` 和 `settings.responseFormat` 覆盖面板默认值。

## B 组：P2 期间顺手修

1. **测试连接容易误报失败。** `settingsApi` 里 `maxTokens: 256` 可能被模型的思考 token 用完，返回 `finish: length`，被报成 `GEMINI_RESPONSE_INCOMPLETE`。带 `-high` 的网关模型尤其容易。改成 `4096`，只按实际生成计费，这条提示词很短。
2. **测试连接的错误要说人话。** 现在界面直接显示 `fetch failed`。按错误码映射成中文：
   - 网络错误 → “连不上这个地址”
   - `GEMINI_API_ERROR` 且 401/403 → “密钥被拒绝”
   - 404 → “模型名或地址不对”
   - `GEMINI_RESPONSE_INCOMPLETE` → “模型没有答完，可换个模型再试”
   - 其他 → 原 message。

   映射放在 `settingsApi`，契约断言 `message` 是中文。
3. **`runsApi` 的 `MODEL_KEY_MISSING` 文案过时。** 现在还写着“在启动服务的终端里设置后重启”，改成“先在设置里填 API 密钥。”。
4. **`worldsApi` 的几处小问题：**
   - `scale` 应取 `pack.meta?.scale`（规格 §7），老世界缺省 `"scene"`。
   - `id` 用目录名，不用 `pack.meta.id`。
   - `POST /api/library/import` 要求 `content-type: application/json`，计划 P1.5 写过。
   - 正文超限时先回 413 再断开连接。现在 `req.destroy()` 在前，客户端只看到连接被重置。
5. **`modelClientContracts` 漏了一个断言。** 第 5 个测试捕获了 `capturedRequest`，但没断言它不含密钥，补上。
6. **进度文档缺两样：**
   - 计划第 6 条要求的“遗留问题”一节。
   - P1.4 第 4 步浏览器走查的记录。
