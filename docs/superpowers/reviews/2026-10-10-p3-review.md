## A. 必须修

### A1 借星的人物名单坏了；河镇的户名是空的

**现象：**
- 借星右侧的人物名单被分成了 3 组，每个头像只有 4 像素宽，基本点不中。组标题有两个是空的，另一个是“其他”。
- 河镇的 5 个户名全是空字符串，所以截图里名单那一行是一串小点。

**原因：**
1. `runsApi.mjs` 的 `worldVisual` 对所有带 `social.boundaries` 的世界都生成 `households`，借星也有这些边界，所以也被分组了。借星甚至有一条 `claimantId: "household:顾家"` 的 fact，所以光按 `household:` 前缀过滤也挡不住它。
2. 查 fact 用的是 `f.id`，但 fact 的主键是 `factId`，所以一条也查不到，`label` 全是 `""`。
3. `ui.js` 把每一户作为一个整块放进 `#roster`，而 `#roster` 仍然是 5 列网格，每户只占 1/5 宽。

**修法：**
- `worldVisual` 只给编译出的小镇（`pack.meta.scale === "town"`）生成 `households`，其余世界一律 `[]`，这样借星、逍遥游的名单走原来的分支，与 P3 之前一致。按 `factId` 匹配 fact，只认 `claimantId` 以 `household:` 开头的。
  ```js
  const facts = new Map((pack.social?.facts || []).map((fact) => [fact.factId, fact]));
  const households = pack.meta?.scale !== "town" ? [] : (pack.social?.boundaries || []).flatMap((boundary) => {
    const claimant = facts.get(boundary.evidenceIds?.[0])?.claimantId || "";
    if (!claimant.startsWith("household:")) return [];
    return [{ label: claimant.slice("household:".length), members: boundary.exemptActorIds || [] }];
  });
  ```
- 分组时给 `#roster` 加一个 class（如 `grouped`），在 CSS 里写 `.roster.grouped { display: block; }`。只有分组时才加这个 class。
- `export` 出 `worldVisual`，在 `observerRunsApiContracts.mjs` 里加断言：
  - 借星、逍遥游的 `households` 都是 `[]`；
  - 编译出的河镇 `households.map((row) => row.label)` 包含“铁家”“林家”“宋家”“陈家”“周家”，且每户成员非空；
  - 河镇的 `startClock` 为 `"08:00"`，借星为 `""`。
- 浏览器验证：
  - 借星名单与 P3 之前一样，5 个头像各约 48 像素宽，没有组标题；
  - 河镇名单每户一行标题，头像正常大小。

### A2 借星的光照层变了

**现象：** 用借星的布局分别按 P3 之前和现在 `main.js` 的方式调用 `lighting.draw`，384×208 的画面里有 15660 个像素不同（约 20%）：
- 晨光斜线（`dawn` 主题的 `sun`）没画；
- 画面四周 2 像素的暗边没画。

**原因：** `main.js` 对所有世界都传 `view`，`lighting.js` 一有 `view` 就走新分支并提前 `return`。新分支漏了 `theme.sun` 和四周暗边。

**修法：**
- `main.js` 只在 v2 世界传 `view` 和 `daylight`，v1 世界的调用与 P3 之前完全相同：`lighting.draw(ctx, t, { litSegments })`。
- 视野分支也补上斜光和暗边，以视野矩形为准（斜光从视野右上角起，暗边画在视野四周），这样小镇画面也有边框。
- 验证：在借星页面的控制台运行下面这段，`diffPixels` 必须为 0。修复后把运行结果写进进度文档。
  ```js
  const { createLighting } = await import('/src/stage/lighting.js');
  const feed = await fetch('/api/runs/<借星存档 id>/feed').then((r) => r.json());
  const layout = feed.world.layout, W = layout.grid.cols * 16, H = layout.grid.rows * 16;
  const render = (opts) => { const c = Object.assign(document.createElement('canvas'), { width: W, height: H }); const g = c.getContext('2d'); g.fillStyle = '#808080'; g.fillRect(0, 0, W, H); createLighting(layout, W, H).draw(g, 12.34, opts); return g.getImageData(0, 0, W, H).data; };
  const before = render({ litSegments: 0 });            // P3 之前 main.js 的调用
  const now = render(/* 现在 main.js 对 v1 世界传的参数，原样抄过来 */ { litSegments: 0 });
  let diffPixels = 0; for (let i = 0; i < before.length; i += 4) if (before[i] !== now[i] || before[i + 1] !== now[i + 1] || before[i + 2] !== now[i + 2]) diffPixels += 1;
  diffPixels;
  ```

### A3 外景上看不到门：屋顶把门盖住了

**现象：** 河镇 5 栋、雾松岭 4 栋房子在外景上都只有一块屋顶，看不到墙和门。人从屋顶边缘凭空出现。

**原因：**
- `tiles.js` 画屋顶时用 `door.between.includes(roof.siteId)` 找门。但 P3.4 已经按计划把 `between[1]` 换成了入口房间的区 id（如 `iron_forge__shop`），所以一扇门也找不到，屋顶盖住了整块地。
- 门在左右两侧的情况（竖街两边的房子，河镇 5 栋里有 3 栋）根本没有处理。

**修法：**
- 在 `src/worlds/layoutGeometry.mjs` 加一个纯函数，按格子找门，不按 id 找：
  ```js
  // Which edge of a building's rect its door is on, found by tile, not by id.
  export function doorOnEdge(rect, doors) {
    const [c, r, w, h] = rect;
    for (const door of doors || []) for (const tile of door.tiles || []) {
      if (!inRect(tile, rect)) continue;
      const [x, y] = tile;
      const edge = y === r + h - 1 ? "bottom" : y === r ? "top" : x === c ? "left" : x === c + w - 1 ? "right" : null;
      if (edge) return { edge, tile };
    }
    return null;
  }
  ```
- `tiles.js` 改用 `doorOnEdge(roof.rect, layout.doors)`，四条边都处理：
  - 门在上下边：留出那一行，画成带门的墙面（现在的写法）。
  - 门在左右边：留出那一列，画成墙（`WALLS.top`，`edge` 取朝外的一侧），再画门。
- 在 `compiledTownMapContracts.mjs` 末尾加断言（只加，不改原有断言）：对每个夹具、每个种子，外景的每个屋顶都满足 `doorOnEdge(roof.rect, exterior.doors)` 不为空，且找到的格子等于该房子 portal 的 `exteriorDoorTile`。
- 浏览器验证：河镇外景每栋房子都能看到门，横街和竖街两边的房子都要看。

### A4 室内房间之间的门洞被墙盖住，空白处画成了一摞摞横梁

**现象：**
- 河镇 5 栋房子共 12 个室内门洞（`style: "opening"`），全部压在 `partition` 墙下，门洞格子也没有地面。画面上房间之间是一整道墙，人像是穿墙走过去的。
- 不属于房间的空白（比如百草堂药房上方的空位、并排房间之间 1 列宽的缝）被拆成一行一条的 `partition`。`partition` 横着画只是一根 16 像素高的横梁，所以空白处看起来像一层层的架子，房间的边界读不出来。

**修法（`interiors.mjs`）：**
- 生成隔墙时跳过所有门洞格子。门洞格子加一条 `floors`，材质取子房间的地面。
- 隔墙按形状分三种：
  1. 上下两排房间之间 1 行高的缝：一条 `w×1` 的 `partition`（横梁）。
  2. 同一排相邻房间之间 1 列宽的缝：一条 `1×h` 的 `partition`。`h > w` 时 `tiles.js` 会画成竖柱。
  3. 其余空白（两个方向都大于 1 格的块）：用 `top` 样式（实心墙顶）。
- 在 `interiorsContracts.mjs` 的“A door for every link”循环里加两条断言（只加，不改原有断言）：
  - 门洞格子不在任何 `walls[].rect` 里：`!map.walls.some((wall) => inRect(tile, wall.rect))`；
  - 门洞格子在某条 `floors[].rect` 里。
- 浏览器验证：百草堂、陈家、周家三栋的室内截图，房间之间能看出门洞，空白处是实心墙。

## B. 应该修

### B1 撤回 `server.mjs` 里 `runsRoot` 的改动

这次顺手把 `runsRoot` 改成了“有 `CHARACTER_TOWN_HOME` 就用 `<home>/runs`”。这不在 P3 范围内，而且是 P7 的事。P7 的要求是迁到数据目录的同时，把旧的 `sim-runs/` 只读并入存档列表。现在这个改法只要设了 `CHARACTER_TOWN_HOME`，`sim-runs/` 里的存档就全部看不到了。

**修法：** 撤回这一行。走查时用 `world:new --out sim-runs/<临时名>`，走查后删掉该目录，计划原本就是这么写的。

### B2 屋顶说话提示改成像素图标

现在是往标签层塞了一个 `kind: "talk"`、文字为“💬”的标签。标签层没有 `talk` 样式，退回成手势样式，emoji 也不是点阵字。

**修法：** 按计划在画布上画一个 13×9 的像素对话框，在世界坐标变换内、屋顶上方居中，每 1/3 秒闪一次。不要用标签层。

### B3 外景灯笼要有光

规划器只放了灯笼的 prop，没有对应的 `lights`。夜里外景一盏灯都不亮，`daylight.lamps` 在外面没有作用。

**修法：** `townPlanner.mjs` 的 `decorate` 放灯笼时，同时在 `map.lights` 里加 `{ at: [x + 0.5, y + 0.5], r: 30, color: "#ffd890" }`。铺子（非住宅）门口也各挂一盏。夜里外景的截图要能看到灯光。
