## 后续真实模型测试

模型固定为 `gpt-5.6-sol`、`medium`，人物会话继续隔离。完整模拟的每日规划、反思、候选和提交均走实际模型供应商；每次调用保存输入、提示、Schema、原始输出、哈希、模型配置和耗时。每个人物回合最多一次协议修正，终止错误结束本次测试，不使用模板补齐数量。

如果反思所依赖的记忆已经耗失，运行时可以完成一次没有新洞见的空反思；报告会明确记录没有新模型输出，不把它计作一次模型返回。

准备全新 40 个人物回合，不调用模型：

```bash
npm run benchmark:model -- --dry-run --fresh --turns 40
```

明确启动真实测试：

```bash
npm run benchmark:model -- --run --fresh --turns 40
```

这里的 40 包含每日规划与反思，不等于 40 段对白或 40 次世界效果。报告分别统计这些数量。默认两调用模式最多允许 120 次供应商请求，包括修正；真实测试会消耗模型额度。本次仅验证准备入口，没有执行上面的真实测试命令。

已有状态可用 `--checkpoint /absolute/path/world-save.json --turns N` 明确继承。继承的历史不计为本次新模型输出，也不宣称已修复旧记忆。原来不传 `--turns` 的两个行动回合基准继续可用。

手工中继从项目目录运行 `npm run relay:start`；需要持久化时显式给出 `RELAY_SAVE_PATH`，恢复时显式给出 `RELAY_RESUME_PATH`。新运行不能覆盖已有输出文件；明确恢复同一文件时才允许继续写入。阶段提交使用 `{ "stageId": "...", "output": { ... } }`。HTTP 202 只是收到回复，协议验收结果查看 `/metrics`。运行时耗时与存档耗时分别记录。
