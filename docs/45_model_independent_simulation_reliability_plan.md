# 与模型选择无关的模拟可靠性方案

状态：已进入实施。依据 2026-09-14 的 [100 回合复核](./44_100_turn_simulation_review.md) 制定；当前实现范围、回归证据与未完成的真实模型验收见 [实施记录 46](./46_reliability_implementation.md)。本文保留设计目标，不代替验收记录。

目标：即使角色模型写错格式、引用错误、夸大行动结果或重复等待，系统也能维持正确的世界状态、感知记录、执行进度与报告，并在无法继续时明确停住。保留人物自己选择目标、行动、情绪调节和对白的权力。

无法保证任意模型都聪明、自然、愿意推进故事。可验收的保证是：错误不能被提升为世界事实；消息不能静默消失；重试和无进展调用不能无限持续；暂停不能伪装成完成。这些保证以受控提交接口、受支持操作及经过验证的运行时为范围。

## 一、先落实的八条约束

| 编号 | 必须保证的行为 | 如何验证 |
|---|---|---|
| G1 | 物品、位置、声音、时间和工作完成只由世界结算产生。 | 任意自由文本均不能产生资源增减或未经结算的公开事实。 |
| G2 | 人物模型没有运行代码、世界存档、故障状态的写权限。 | 所有模型适配器只能读本人上下文并提交阶段响应；不存在直接写存档的旁路。 |
| G3 | 角色自主选择；程序不替其补选行动、承诺、情绪表现或对白。 | 错误输出只能要求同一角色修正、记录失败或暂停，不能自动选最高分候选。 |
| G4 | 已投递消息必须有明确去向。 | 保留待处理、已呈现、已注意、已解释、明确延后/忽略、感知过期等记录，禁止按整批唤醒无条件清空。 |
| G5 | 同一阶段的输入、允许引用和校验状态保持一致。 | 模型看到的情绪快照就是该次表达校验使用的快照；世界变化另走行动重验。 |
| G6 | 重复提交、超时和崩溃恢复不重复执行行动。 | 同一提交键最多对应一次世界事件；恢复从已保存阶段继续。 |
| G7 | 无新信息的等待不持续消耗模型调用。 | 等待注册条件后进入休眠；真实事件、截止时间或身体变化才唤醒。 |
| G8 | 运行结束与事务完成分别统计。 | 用满 100 回合仅表示预算用完；柴水完成、比试发生等必须有对应结算证据。 |

## 二、统一提交接口，缩小模型需要掌握的规则

复用现有 [阶段提交模块](../src/server/simulation/characterStageSubmission.mjs) 与 [人物阶段协议](../src/server/simulation/characterAgentTurnProtocol.mjs)，将其作为所有模型适配器共同经过的 Interface。自动运行器、Pi 中继、产品运行入口都不能另有一套宽松路径。

建议公开两个操作，其他校验细节留在模块内部：

```text
prepareStage(characterSession)
  -> stageTicket + 本人上下文 + 精简输出合同

submitStage(stageTicket, authoredOutput)
  -> accepted | repair_required | suspended_model_error
```

`stageTicket` 由服务端记录并绑定角色、阶段、上下文版本、允许引用、schema 版本与快照摘要。模型不手写角色归属、长回合号、世界版本、模型来源或结算成功标志。过期票据、错角色引用和未知字段明确拒绝；票据不是模型可以自填的 `trusted: true`。

角色模型运行在受限执行器内，只拥有本人上下文和提交操作。开发代理可以修改工程，但不作为运行中的角色执行器使用。保留 Pi 等通用工具时，需通过系统沙箱或独立权限限定可写路径；若仍让模型任意修改同一份世界存档，就不能声称 G2 成立。恢复必须经过受控恢复接口，不能靠编辑 `halted=false` 继续。

模型不支持结构化输出时，可经 JSON 解析适配器进入同一 Interface。适配器只做确定性的封装、固定元数据填充和格式处理，不猜测人物本意，不替模型选择引用、情绪来源或候选。

## 三、把物理操作与文字表达分开

### 3.1 收口实际操作

严格运行模式取消 `act + bodyDelta -> gesture` 的默认兼容转换。修改位置包括 [tavernCharacterAgentV2.mjs](../src/server/pipeline/tavernCharacterAgentV2.mjs)、[tavernWorldRuntimeV27.mjs](../src/server/pipeline/tavernWorldRuntimeV27.mjs) 和 [worldActionRegistry.mjs](../src/server/simulation/worldActionRegistry.mjs)。

人物先生成自己的候选，再用有定义的操作表达所选行动，例如拿起物品、放下物品、移动、执行一束柴的工作、添水、休息或等待。操作句柄和对象句柄来自本人可感知的操作表。模型可以选择失败风险高、违反社会期待或中断原目标的行动；操作表不能变成只允许“正确剧情”的菜单。

程序检查物理条件和结算后果。合法但条件不满足的行动可以产生失败结果，例如对空杯执行饮用；不能为了减少报错自动把杯子填满。未知动作保留为 `unsupported_intent` 并请人物改为可表达的动作，不能自动降级成“做了一个成功手势”。

### 3.2 自由文字不能再作为物理事实来源

当前不仅手势会直接转发原文，观察、说话附带动作、物品操作和工作过程也有类似路径。因此只封掉 `act` 不足以完成修复。

| 内容 | 权限和处理 |
|---|---|
| 实际行动与身体动作 | 使用可组合、可扩展的结构化操作；朝向、幅度、速度、目标等参数由人物选择。 |
| 物理结果、动作声音、物品变化 | 从实际结算、身体状态和过程事件产生，同一事件关联视觉、听觉和资源变化。 |
| 人物字面对白 | 由人物生成并保留原话；即使他说“柴都劈完了”，世界只记“他说了这句话”，不据此完成柴务。 |
| 私人意图与解释 | 保留在本人记录中，可以犹豫、误判、隐瞒；不作为他人的直接感知。 |
| 未经结构化支持的动作散文 | 仅进入审计草稿，不进入实际场景叙述、他人感知或完成度统计。 |

权威场景描述由已结算事实与人物选择的合法动作参数生成。最初可用确定性呈现规则；不再让第二个模型审核散文后决定物理事实。规则可以支持更多表演动作，但不能把自由文本语义识别当作“任意模型都安全”的最后防线。

这会收紧未实现动作的表现范围，需要在真实样本中检查表演是否僵硬。宁可明确记录暂不支持，也不把动作文字假装成物理能力。对白仍由人物自由生成，不能套用固定剧情台词。

### 3.3 先打通柴、水、茶、交付四条实际路径

复用 [workCapability.mjs](../src/server/simulation/workCapability.mjs)、[serviceCapability.mjs](../src/server/simulation/serviceCapability.mjs)、[worldCapabilityRegistry.mjs](../src/server/simulation/worldCapabilityRegistry.mjs)、[durativeWorldProcess.mjs](../src/server/simulation/durativeWorldProcess.mjs) 和 [objectLedger.mjs](../src/server/simulation/objectLedger.mjs)。现有柴务已有每束 42 秒和资源增减，不必重写通用世界引擎。

以一束柴为例：人物明确选定工作范围；必须满足拿到工具、到达地点等条件；开始后创建过程，经过规定时间、检查中断，再完成这一束。完成时同时记录湿柴减少、成柴增加、身体负荷、实际声音和工作进度。没有资源变化就不能报告这一束加工完成。

首版保留明确的开始、完成、中断语义。可随后增加人物明确选择的“执行这一单位直到完成或被打断”，使程序推进已授权过程，而非每个举斧、吸气步骤都询问模型。程序不能据“想做完家务”自动替人物拿工具、决定做多少束或继续下一项工作。

水和茶必须有内容物变化；药包与清单分别绑定物品操作。单物品动作只能改变该物品；若提供多物品操作，必须逐项验证并事先定义全成全败或允许部分成功，报告逐项结果。

## 四、统一使用实际状态下的三次调用

复用当前已有的 three-call 路径及 [三次调用合同](../scripts/tavernV27ThreeCallContracts.mjs)。新严格运行的所有入口统一为：

```text
1. 人物理解当前处境，提出候选
   -> 程序计算心理状态与候选评价
2. 人物选择行动和情绪调节
   -> 程序计算实际调节结果，冻结表达快照
3. 同一人物决定对白和表达
   -> 校验后提交世界行动
```

评价器保持 `selection: null`，最终选择仍由人物完成。禁止在第二步之前预估若干表达现场，再用第二步之后的状态否定同一份响应。

进一步减少需要模型重复声明的派生字段：活情绪集合和数值由程序记录；模型选择如何承受、调节、表现。将“运行时有哪些情绪”与“人物主动选择怎样表达”拆开，避免让模型手抄已知集合、错误宣告没有活情绪。程序不能自动代填“人物决定压住情绪”，也不能代选泄漏通道。主观选择缺失仍需修正或暂停。

表达快照使用同一个对象生成输入、schema 和校验依据。若角色阶段已被取消或替换，旧响应判为过期；若只是客观世界在期间发生变化，已选行动在世界提交处按当前状态重验，明确返回真实后果，不能静默改写人物的选择。

## 五、消息不静默丢失，注意力只决定重点

改动 [characterPerception.mjs](../src/server/simulation/characterPerception.mjs)、[characterEventReceipts.mjs](../src/server/simulation/characterEventReceipts.mjs)、[characterSessionActor.mjs](../src/server/simulation/characterSessionActor.mjs) 和 [characterWorldRuntime.mjs](../src/server/simulation/characterWorldRuntime.mjs)。

1. 已能听清且明确对自己说的新话，进入本次上下文的必呈现区；噪声、遮挡、昏迷等感知条件仍由世界与感知模块处理，不能变成全知。
2. 将稳定背景与新事件分开。佩剑、已有姿势等稳定信息不在每次来话时重新竞争一个新消息名额；上一行动反馈压缩为对应结算记录。
3. 同一决策前来自两人的有效新请求都保留各自来源和时间，人物可以先回应其中一人、延后或忽略另一人；程序不替他指定优先对象。
4. 逐条记录消息处理状态。没有被呈现或处理的消息不能因为整批 wake 完成而被删掉。延后消息保留原时间，不能日后装作刚刚发生。
5. 旁听和弱信号可受注意力限制；若短暂感知已过期，记录具体原因并进入审计存档，不能标成已经理解。审计历史不等于人物拥有的记忆。
6. 超过上下文容量时分页或保留待处理项，不能静默截断。保护必呈现消息的预算，避免稳定背景挤掉直接提问。

必呈现不等于强迫回答。人物仍可无视对方，区别在于这是可追踪的角色处理，而不是程序漏发了输入。

## 六、让等待成为过程，并保证重新判断的机会

### 6.1 等待和休息

新增明确的等待合同，至少包含本人选择的唤醒条件、截止时间和可打断条件。例如等对方回应、等手上工作完成、休息到某时刻；不是模糊地输出一次“耳门当值”。

等待注册后，运行时休眠该角色的调用。已经存在的姿态不重复广播为新事件。到期过程、真实新消息、紧迫身体变化或所选条件触发时，再唤醒一次；多人都在等待时推进到最近的有效世界事件或期限，而非逐个反复问“还等不等”。

系统判断条件是否触发，人物决定醒来之后做什么。等待没有确定对象或期限时，要求角色补充可执行条件，不能替它设定一场必然发生的比试。

### 6.2 调度公平与无进展保护

保留紧迫事件的抢占；对普通证据、已到期计划和反思引入公平排序。首版默认：反思/计划到期后，最多经过 3 个该角色的非紧迫决策机会就必须获得调度机会。持续紧迫事件导致无法满足时记录明确的紧迫阻塞，而非报告反思已经处理。

无进展检测使用角色、操作、目标、已结算相关效果和本人有效新证据；不依靠自由文字换个说法，不把纯时钟增长、新日志 ID 或无依据的置信度抖动当成推进。正常休息恢复和已注册等待不按空转惩罚。

首版默认：相同语义行动连续 3 次没有新证据或相关效果，给同一角色一次明确的私人复核机会；若再次提交等价空转，暂停该角色的自动推理并标为 `stalled`。这是暂停执行器调用，不是假造角色认输、决定沉默或转去工作。其他能够继续的角色仍可运行；若全体停滞，运行状态明确为停滞。

这组阈值属于可配置的调用治理规则，不是人物性格。它保证有限调用内暴露无进展，不能保证换任何模型都会选择有价值的行动。

## 七、有限修复与可靠恢复

协议问题、世界中的行动失败和程序异常分开处理：

| 情况 | 处理 |
|---|---|
| 错字段、无效引用、阶段输出不合规 | 返回准确字段、允许值和冻结上下文，同一角色在原阶段修正。 |
| 合法行动遇到客观失败 | 记录失败后果，交给人物理解；不把它当格式错误反复补交。 |
| 相同错误持续出现 | 每个人物决策最多追加 2 次模型修复，总调用上限 5 次（三个正常阶段加两次修复）。超限暂停该角色，保留现场。 |
| 重复请求或提交后连接断开 | 查询原提交结果；相同提交键、相同内容返回原结果，不再次执行；同键不同内容拒绝。 |
| 程序异常或进程中断 | 从持久化阶段恢复；不清空故障标志后跳到下一人，不能把未结算回合计入完成。 |

计数必须跨阶段、跨恢复保留，不因新建阶段号、重启或更换措辞归零。请求的时长、token 和总运行调用预算也需要独立上限；达到预算返回暂停状态，不生成替代对白或成功动作。

持久化划分为：`stage_accepted`、`world_attempt_prepared`、`world_outcome_committed`、`turn_finalized`。复用 [worldCommitCoordinator.mjs](../src/server/simulation/worldCommitCoordinator.mjs) 的串行结算，在其外围补齐阶段日志和待提交记录。已经接受的私人理解与选择不因后来表达错误重复生成；其接受记录与未完成行动必须能恢复。拒绝稿不能写世界；世界行动完成后只投递一次；消息按实际已接受的处理状态逐项结账。

## 八、报告只能引用实际事件

扩展 [settledSimulationReport.mjs](../src/server/simulation/settledSimulationReport.mjs)，区分：模型调用、私人决策、世界行动尝试、成功/部分成功/失败、过程步骤、客观任务完成。自动推进的工作步骤不能冒充新的人物决策回合。

场景的终局判据读取客观数据：加工了多少束柴、水量变化、药包与清单是否交接并验收、共同活动是否实际开始/完成。承诺“稍后比试”只算承诺，不算比试发生。人物心理进展可以另列，但不能替代物理任务完成，也不据此自动评分文学质量。

统一运行结束原因：`turn_limit_reached`、`scenario_condition_reached`、`waiting`、`stalled`、`suspended_model_error`、`runtime_error`。`complete` 若保留，只用于明确标明的运行流程完成，不作为剧情完成同义词。

记录每阶段的原始输入、输出、拒绝码、实际模型配置、时间与恢复链。无法核实模型身份时保留 `external-unverified`。报告可以引用人物原话，但自动叙述不得从动作草稿推导“第五斧”之类事件数量。

## 九、实施顺序与完成标准

按五个能单独复核的批次实施，不重写整个项目，不增加一个代替人物决策的导演模型。

| 批次 | 工作范围 | 完成标准 |
|---|---|---|
| 1. 固定反例与封住旁路 | 保存已发现反例；受控模型执行器；取消自由动作文字作为权威事实的入口。 | 无论通过自动运行器还是中继，伪造劈柴、倒茶、移动的文字都不能写入对应事实或他人感知。 |
| 2. 完成实际操作链 | 柴、水、茶、双物品交付；身体、声音、资源与过程结算关联。 | 正确操作能完成；工具不足、中断、部分交付和失败得到一致结果，不靠散文补全。 |
| 3. 稳定阶段与恢复 | 全入口 three-call；缩减派生字段；快照合同、提交去重、有限修复、恢复日志。 | 活情绪前后漂移不再制造固有拒绝；永远写错的模型在预算内明确暂停，重启不重复结算。 |
| 4. 修复消息与等待调度 | 逐条消息处理、背景去重、等待订阅、反思公平排序、停滞检测。 | 两条新请求都能进入相应上下文；安静等待不形成调用风暴；反思满足调度上限。 |
| 5. 报告与模型验收 | 统一事件报告；对抗输入与真实模型逐步测试。 | 运行次数、失败、停滞、任务完成和模型来源都能从日志重算。 |

每批通过对应合同后再进入下一批。前三批解决错误结果与重复协议拒绝，第四批解决空转，第五批验证它们在完整运行中确实共同成立。

## 十、测试矩阵

硬约束先用可控适配器验证，不依赖某个强模型碰巧写对。随后才进行真实模型质量测试。

| 测试 | 必须得到的结果 |
|---|---|
| 原第 52 回合：act 文本说“木头劈开” | 明确要求使用有效操作；不产生加工、脆响或“木头已开”的感知。 |
| observe/rest/speak 附带文字说已经移动或拿斧 | 对应物理结果不能进入世界或他人感知；对白中的陈述只作为原话保留。 |
| 未持斧就尝试工作 | 得到缺工具的真实失败或未开始结果，成柴不增加。 |
| 有工具、位置正确、完成一束柴 | 规定时间后资源增减一次、身体负荷和可传播声音一致；中断不冒充完成。 |
| 空杯“倒满”、随后饮用 | 没有真正注入茶就仍为空；饮用明确失败。 |
| 药包与清单交付 | 每一物品各有明确结果；只操作药包不能声称清单也交付。 |
| 两人同时向真石提问，另有旧反馈和佩剑背景 | 有效直接请求均保留；他可自行延后其中一条，但不能被背景容量静默删除。 |
| 旁听过期或听觉受阻 | 有明确感知处置；不伪造听到，也不把审计历史变成人物记忆。 |
| 空/错 JSON、虚构引用、错误情绪声明的适配器 | 有界修复后暂停，无假动作、无假台词、无丢回合。 |
| 同一提交重复发送，或结算后立刻崩溃 | 只存在一个相应世界后果；恢复后返回原结果。 |
| 角色选择安静等待 10 分钟且无人打断 | 一次决策建立等待，期间不逐轮调用该角色；到期按条件唤醒。 |
| 永远重复准备动作的适配器 | 在停滞预算内进入复核/暂停；不能自动强迫角色开始劈柴。 |
| 已到期反思同时遇到普通姿态消息流 | 在不超过 3 个非紧迫机会内获调度；紧迫阻塞单独记录。 |
| 台词谎称“柴做完了” | 世界记原话，柴务不变；他人可自行相信或怀疑，报告不替谎话背书。 |
| 任意动作草稿、局部失败与预算结束混合 | 自动报告的资源、完成数和状态与事件日志逐项一致。 |

增加随机字段、未知引用、同键异文、次序颠倒等生成式测试，确保所有适配器经过同一约束。事件事实投影使用“只保留已证明字段”的正向规则，不用关键词黑名单阻止自由文字。

真实模型验证建议沿用 Luna high、Sol medium：先各跑 10 个人物决策，检查初次合规率、修复次数、任务进展与表现；通过后各做更长运行，最后以 100 回合观察长期循环。身份由实际提供方日志验证；不能从模型自称推断。此处只是后续测试计划，本次没有启动模型调用。

验收分两层：G1–G8 是各适配器必须满足的运行约束；对白自然度、主动性、是否选择完成某件事由真实输出与人工审阅判断。永远只输出垃圾的模型可以无法完成任务，但系统必须在有限时间和成本内明确失败，不能演出一个虚假的成功世界。

## 十一、旧存档与发布

旧 100 回合存档和原始响应保持原样作为证据，不能按“劈了五斧”的文字补造资源。新严格模式采用明确的协议版本；新运行禁止绕过它调用旧宽松入口。当前未提交工作较多，实施时单独记录各批次修改范围与验证结果。

完整验证从干净初始世界和新人物会话开始，避免旧会话已经形成的错误自述污染新样本。恢复旧世界时只在分支副本上做显式迁移，旧自由动作描述标为历史未核实材料，不能自动修正人物信念或反写原历史。旧运行没有完整保存所有阶段输入，不能宣称它能在新协议下逐步等价重放；应把关键错误缩成可重现的反例，再以新日志验证全链路。

发布条件：没有错误文字提升为世界事实，没有静默丢失的消息，没有重复世界结算或无界重试；每个实际支持的操作均有成功与失败路径证据。若模型质量不足，报告明确指出不足，不降低约束来追求 100 回合的完成数字。
